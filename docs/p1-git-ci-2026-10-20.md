- 后续文档提交仍会继续推送到同一远端。

### 2.2 CI 现状

**已完成（静态 + 本地等价）**：

- `.github/workflows/ci.yml` 步骤与本地门禁一致：`design:check → typecheck → build → test → coverage → 服务端真实启动冒烟 → 体积告警`。
- 服务端冒烟步骤的命令链（登录 → 取 token → `/auth/me`）已在本地按同等路径跑通。
- coverage 命令已含 `--no-file-parallelism`（B-45），本地 67 文件 1032 例 78.18s，低于常见 30 分钟 job 上限。
- 构建产物路径 `apps/server/dist/main.js` 存在（P0 `pnpm -r build` 已生成）。
- **Gitee Go 兼容性（官方文档已确认）**：`build@nodejs` 仅支持 Node **8.16.2 / 10.17.0 / 12.16.1 / 14.16.0 / 15.12.0**，基础镜像 CentOS 7.6；本项目要求 Node ≥20（实测 22.23.2），**无法直接使用**（来源：`https://help.gitee.com/gitee-go/plugin/ci-build`）。替代方案：Docker 插件需远程镜像仓库凭据、`shell@agent` 需自托管主机；因此当前最现实的是 **GitHub 镜像跑现有 Actions**。
