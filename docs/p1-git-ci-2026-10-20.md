## 2. CI 核对结果

### 2.1 远端推送（未完成，凭据阻塞）

- 远端：`https://gitee.com/Richardlichengyu/lowcode.git`（公开仓库，已有 Gitee 模板 `README.md` / `README.en.md`）。
- 已完成：`git remote add origin`；`git ls-remote` 成功；`git fetch origin` 成功；合并远端初始提交（保留本项目 README，移除模板 `README.en.md`）；本地分支由 `main` 改为 `master` 对齐远端默认分支。
- **失败**：`git push -u origin master` 返回 `Authentication failed`，Gitee 提示 `18186473822: Incorrect username or password (access token)` —— Windows 凭据管理器里存的是旧账号/失效令牌，**不是本次代码问题**。
- 未完成：推送、远端首次构建、Gitee 侧 CI。
- 解决：在 Gitee「设置 → 私人令牌」生成 `projects` 权限令牌，然后执行 `git push` 并用用户名 `Richardlichengyu` + 令牌作为密码；或先在 Windows 凭据管理器删除旧的 `git:https://gitee.com` 凭据再推。

### 2.2 CI 现状

**已完成（静态 + 本地等价）**：

- `.github/workflows/ci.yml` 步骤与本地门禁一致：`design:check → typecheck → build → test → coverage → 服务端真实启动冒烟 → 体积告警`。
- 服务端冒烟步骤的命令链（登录 → 取 token → `/auth/me`）已在本地按同等路径跑通。
- coverage 命令已含 `--no-file-parallelism`（B-45），本地 67 文件 1032 例 78.18s，低于常见 30 分钟 job 上限。
- 构建产物路径 `apps/server/dist/main.js` 存在（P0 `pnpm -r build` 已生成）。
- **Gitee Go 兼容性（未验证）**：官方 Node 构建插件只提供固定版本下拉，文档未列出可选版本；本项目要求 Node ≥20（实测 22.23.2），**能否直接选用 20/22 尚未实测**。保守方案是 Docker 插件（`node:22` 镜像）、自托管 `shell@agent`，或 **GitHub 镜像跑现有 Actions**。
